# CSAPP 章节翻译命令

## 任务

将文件 `$ARGUMENTS` 的内容翻译成中文。

### 2. 格式保持

- 保留所有 Markdown 格式（标题、列表、代码块、引用等）
- 代码块内容不翻译，保持原样
- 保留图片引用和链接格式
- **数据表不翻译**：表格内容主要由数字、单字母、十六进制值或公式数据组成的表格，保持原样不翻译（如：数值对照表、编码转换表、位运算示例表等）
- LaTeX 公式使用 Markdown 兼容语法：
  - 行内公式：`$...$`（如 `$T_{\text{old}}$`）
  - 块级公式：`$$...$$`
  - 不要使用 `\(` `\)` 或 `\[` `\]` 语法
- **练习题格式**：使用加粗文本而非标题（如：`**练习题 2.1（答案见第 XXX 页）**`）
- **旁注格式**：必须使用引用块格式（以 `>` 开头），格式为：
  ```markdown
  >**旁注 标题**
  >
  >旁注内容...
  ```

### 3. 分页批量翻译策略

**核心思路**：扫描文档中所有 `<!-- Page XXXX -->` 标记，按每批最多 10 页逐批翻译，直接追加写入输出文件，无需生成中间分割文件。

**执行流程**：
1. 扫描所有 `<!-- Page XXXX -->` 标记，得到总页数 P
2. 计算批次数 = `ceil(P / 10)`
3. 对第 i 批（i = 1, 2, ...）：
   - 提取第 (i-1)×10+1 页到第 min(i×10, P) 页的内容
   - 翻译该批内容（应用术语表、标题规范、旁注格式等）
   - 写入输出文件（第 1 批用 Write 创建；后续批次用 Edit 追加）
   - 输出进度："✓ 已完成第 X-Y 页（共 P 页），第 i/N 批"
4. 全部完成后输出："✓ 翻译完成，共 P 页，输出至 <文件路径>"

**关键细节**：
- 保留 `<!-- Page XXXX -->` 标记，不翻译
- 第 1 批写入时包含文件头（一级标题）
- 如果文档无页码标记，退化为按 `##` 标题分段翻译

### 4. 翻译风格

- 使用正式、学术的中文表达
- 保持原文的技术准确性
- 长句适当拆分，符合中文阅读习惯
- 专有名词首次出现时可保留英文原文（如：虚拟内存 (Virtual Memory)）

### 5. 异常处理

当遇到以下情况时，**跳过该部分**并在文档中添加标注：

1. **特殊 Unicode 字符**：文件包含无法正确处理的特殊字符（如乱码、不可见字符）
2. **格式严重损坏**：原文格式混乱，无法识别段落边界
3. **PDF 提取错误**：从 PDF 提取时产生的断行、错位等问题
4. **公式渲染问题**：数学公式无法正确解析

**标注格式**：
```markdown
<!-- [未翻译] 原因: {具体原因} -->
<!-- 原文开始 -->
{保留原文内容}
<!-- 原文结束 -->
```

**示例**：
```markdown
<!-- [未翻译] 原因: PDF提取导致公式格式损坏 -->
<!-- 原文开始 -->
B2Tw(⃗x) .= −xw−12w−1 +
<!-- 原文结束 -->
```

## 执行步骤

1. **读取文件**：读取 `$ARGUMENTS` 指定的文件
2. **确定输出路径**：从参数推断输出文件路径
   - 例：`raw_texts/06-xxx.md` → `chapters/06-中文名.md`
   - 如无法推断，询问用户
3. **扫描页码标记**：统计文档中所有 `<!-- Page XXXX -->` 标记，得到总页数 P
4. **计算批次**：批次数 = `ceil(P / 10)`；如无页码标记，按 `##` 分段翻译
5. **逐批翻译并写入**：
   - 第 1 批：Write 创建输出文件（含文件头）+ 翻译内容
   - 第 2+ 批：Edit 追加翻译内容到输出文件
   - 每批完成后输出进度信息
6. **完成确认**：输出最终统计并确认输出文件

### 6. 标题编号规范

CSAPP 章节文档必须严格遵循以下标题层级规范：

**标题层级规则**：
- **一级标题**：`# 第 XX 章：章节名称`
- **二级标题**：`## X.1`、`## X.2`、`## X.3`...（主要章节）
- **三级标题**：`### X.1.1`、`### X.1.2`...（子章节）
- **四级标题**：`#### X.1.1.1`、`#### X.1.1.2`...（更细子节，如有）

**关键原则**：标题级别（`#` 数量）必须与编号深度一致
- 两位编号（如 `2.1`）→ 二级标题 `##`
- 三位编号（如 `2.1.1`）→ 三级标题 `###`
- 四位编号（如 `2.1.1.1`）→ 四级标题 `####`

**示例**：
```markdown
## 2.1 信息存储

### 2.1.1 十六进制表示法

#### 2.1.1.1 详细说明（如有此级别）
```

**常见错误**：
- ❌ `### 2.2 整数表示`（三级标题用于二位编号）
- ✅ `## 2.2 整数表示`（二级标题用于二位编号）
- ❌ `#### 2.2.1 整数数据类型`（四级标题用于三位编号）
- ✅ `### 2.2.1 整数数据类型`（三级标题用于三位编号）

**特殊内容格式**：
- **旁注**：使用引用块格式 `>**旁注 标题**`，每行以 `>` 开头（已在第2节说明）
- **练习题**：使用加粗格式 `**练习题 X.XX ☐**`，不使用标题（已在第2节说明）
- **原理/推导/补充说明**：保持二级标题 `##`（符合规范）

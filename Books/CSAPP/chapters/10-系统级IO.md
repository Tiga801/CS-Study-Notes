输入/输出（I/O）是在主内存与外部设备（如磁盘驱动器、终端和网络）之间复制数据的过程。输入操作将数据从 I/O 设备复制到主内存，输出操作将数据从内存复制到设备。

所有语言运行时系统都提供执行 I/O 的更高级工具。例如，ANSI C 提供了标准 I/O 库，其中有 `printf` 和 `scanf` 等执行带缓冲 I/O 的函数。C++ 语言通过重载 `<<`（"放入"）和 `>>`（"取出"）运算符提供类似功能。在 Linux 系统上，这些高级 I/O 函数是用内核提供的系统级 Unix I/O 函数实现的。大多数情况下，高级 I/O 函数运行良好，无需直接使用 Unix I/O。那么，为什么还要费心学习 Unix I/O 呢？

- **理解 Unix I/O 将有助于理解其他系统概念。** I/O 是系统运行不可或缺的一部分，因此我们经常遇到 I/O 与其他系统概念之间的循环依赖。例如，I/O 在进程创建和执行中起着关键作用。反过来，进程创建在不同进程如何共享文件方面也起着关键作用。因此，要真正理解 I/O，就需要理解进程，反之亦然。我们在讨论内存层次结构、链接和加载、进程以及虚拟内存时已经涉及了 I/O 的某些方面。现在你对这些概念有了更深入的理解，我们可以闭合这个圆，更详细地深入研究 I/O。

- **有时你别无选择，只能使用 Unix I/O。** 在某些重要情况下，使用高级 I/O 函数要么不可能，要么不合适。例如，标准 I/O 库没有提供访问文件元数据（如文件大小或文件创建时间）的方法。此外，标准 I/O 库存在一些问题，使其在网络编程中使用起来有风险。

本章向你介绍 Unix I/O 和标准 I/O 的一般概念，并展示如何在 C 程序中可靠地使用它们。除作为一般性介绍外，本章还为我们后续学习网络编程和并发奠定坚实基础。

## 10.1 Unix I/O

Linux 文件是 m 个字节的序列：

$$B_0, B_1, \cdots, B_k, \cdots, B_{m-1}$$

所有 I/O 设备（如网络、磁盘和终端）都被模型化为文件，所有的输入和输出都通过读写相应的文件来执行。这种将设备优雅地映射到文件的方式，使 Linux 内核能够导出一个简单的低级应用接口，称为 Unix I/O，它使所有输入和输出都能以统一一致的方式执行：

---

<!-- Page 0914 -->

**打开文件。** 应用程序通过请求内核打开相应的文件来宣告它想要访问某个 I/O 设备。内核返回一个小的非负整数，称为描述符，它在此后所有对该文件的操作中标识这个文件。内核记录有关打开文件的所有信息，应用程序只需记录描述符。

每个由 Linux shell 创建的进程一开始都有三个打开的文件：标准输入（描述符 0）、标准输出（描述符 1）和标准错误（描述符 2）。头文件 `<unistd.h>` 定义了常量 `STDIN_FILENO`、`STDOUT_FILENO` 和 `STDERR_FILENO`，可以用来代替显式的描述符值。

**改变当前的文件位置。** 对于每个打开的文件，内核保持着一个文件位置 k，初始值为 0。文件位置是从文件开头起始的字节偏移量。应用程序可以通过执行 seek 操作，显式地将当前文件位置设置为 k。

**读写文件。** 读操作从文件的当前位置 k 开始，将 n > 0 个字节复制到内存，然后将 k 增加 n。对于一个大小为 m 字节的文件，当 $k \geq m$ 时执行读操作会触发一个称为文件结束（EOF）的条件，应用程序可以检测到这个条件。文件结尾处并没有显式的"EOF 字符"。

类似地，写操作从内存复制 n > 0 个字节到文件，从当前文件位置 k 开始，然后更新 k。

**关闭文件。** 当应用程序完成对文件的访问后，它通过请求内核关闭该文件来通知内核。内核的响应是释放在打开文件时创建的数据结构，并将描述符恢复到可用描述符池中。当进程由于任何原因终止时，内核关闭所有打开的文件并释放其内存资源。

## 10.2 文件

每个 Linux 文件都有一个类型，用于说明它在系统中的角色：

- **普通文件**（regular file）包含任意数据。应用程序通常区分文本文件（只包含 ASCII 或 Unicode 字符的普通文件）和二进制文件（其他所有文件）。对内核而言，文本文件和二进制文件没有区别。

  Linux 文本文件由一系列文本行组成，每行是一个以换行符（`'\n'`）结尾的字符序列。换行符与 ASCII 换行符（LF）相同，数值为 0x0a。

- **目录**（directory）是由一组链接组成的文件，每个链接将一个文件名映射到一个文件，该文件可能是另一个目录。每个目录至少含有

>**旁注 行结束（EOL）指示符**

>处理文本文件的一个烦人方面是不同系统使用不同的字符来标记行的结束。Linux 和 Mac OS X 使用 `'\n'`（0xa），即 ASCII 换行符（LF）。然而，MS Windows 和互联网协议（如 HTTP）使用序列 `'\r\n'`（0xd 0xa），即 ASCII 回车符（CR）后跟换行符（LF）。如果你在 Windows 中创建文件 `foo.txt` 然后在 Linux 文本编辑器中查看，你会在每行末尾看到令人烦恼的 `^M`，这是 Linux 工具显示 CR 字符的方式。你可以通过运行以下命令就地删除 `foo.txt` 中多余的 CR 字符：

- **套接字**（socket）是用于通过网络与另一个进程通信的文件（第 11.4 节）。

目录层次结构中的位置由路径名指定。路径名是一个由可选斜杠后跟一系列以斜杠分隔的文件名构成的字符串。路径名有两种形式：

## 10.3 打开和关闭文件

进程通过调用 `open` 函数来打开一个已存在的文件或者创建一个新文件。

```c
#include <sys/types.h>
#include <sys/stat.h>
#include <fcntl.h>

int open(char *filename, int flags, mode_t mode);
返回：若成功则为新文件描述符，若出错则为 -1
```

`open` 函数将 `filename` 转换为一个文件描述符，并返回描述符数字。返回的描述符总是在进程中当前没有打开的最小描述符。`flags` 参数指明进程打算如何访问这个文件：

- `O_RDONLY`：只读
- `O_WRONLY`：只写
- `O_RDWR`：可读可写

例如，下面是如何以只读方式打开一个已存在的文件：

```c
fd = Open("foo.txt", O_RDONLY, 0);
```

`flags` 参数也可以与一个或多个位掩码进行或运算，为写提供额外的指示：

- `O_CREAT`：如果文件不存在，则创建一个截断的（空）文件。
- `O_TRUNC`：如果文件已存在，则截断它。
- `O_APPEND`：在每次写操作之前，将文件位置设置到文件结尾。

例如，下面是如何以追加数据为目的打开一个已存在文件：

```c
fd = Open("foo.txt", O_WRONLY | O_APPEND, 0);
```

`mode` 参数指定新文件的访问权限位。这些位的符号名如图 10.2 所示。

作为其上下文的一部分，每个进程都有一个 umask，它是通过调用 `umask` 函数来设置的。当进程通过带某个 `mode` 参数的 `open` 函数调用创建一个新文件时，文件的访问权限位被设置为 `mode & ~umask`。例如，假设我们为 `mode` 和 `umask` 提供了以下默认值：

```c
#define DEF_MODE    S_IRUSR | S_IWUSR | S_IRGRP | S_IWGRP | S_IROTH | S_IWOTH
#define DEF_UMASK   S_IWGRP | S_IWOTH
```

那么以下代码片段将创建一个新文件，其中文件所有者有读写权限，所有其他用户都有读权限：

```c
umask(DEF_UMASK);
fd = Open("foo.txt", O_CREAT | O_TRUNC | O_WRONLY, DEF_MODE);
```

最后，进程通过调用 `close` 函数来关闭一个打开的文件。

```c
#include <unistd.h>
int close(int fd);
返回：若成功则为 0，若出错则为 -1
```

## 10.4 读和写文件

应用程序分别通过调用 `read` 和 `write` 函数来执行输入和输出。

```c
#include <unistd.h>

ssize_t read(int fd, void *buf, size_t n);
    返回：若成功则为读取的字节数，若为 EOF 则为 0，若出错则为 -1

ssize_t write(int fd, const void *buf, size_t n);
    返回：若成功则为写入的字节数，若出错则为 -1
```

`read` 函数从描述符 `fd` 的当前文件位置最多复制 n 个字节到内存位置 `buf`。返回值为 -1 表示错误，返回值为 0 表示 EOF。否则，返回值表示实际传送的字节数。

`write` 函数从内存位置 `buf` 最多复制 n 个字节到描述符 `fd` 的当前文件位置。图 10.3 展示了一个使用 `read` 和 `write` 调用将标准输入逐字节复制到标准输出的程序。

应用程序可以通过调用 `lseek` 函数来显式修改当前文件位置，该函数不在本书讨论范围之内。

在某些情况下，`read` 和 `write` 传送的字节比应用程序要求的少，这样的不足值（short count）并不表示出错。产生不足值的原因有很多：

>**旁注 ssize_t 和 size_t 的区别是什么？**
>
>你可能注意到 `read` 函数有一个 `size_t` 输入参数和一个 `ssize_t` 返回值。那么这两种类型有什么区别？在 x86-64 系统上，`size_t` 被定义为 `unsigned long`，而 `ssize_t`（有符号大小）被定义为 `long`。`read` 函数返回有符号大小而非无符号大小，是因为它必须在出错时返回 -1。有趣的是，返回 -1 的可能性将一次读取的最大字节数减少了一半。

```c
#include "csapp.h"

int main(void)
{
    char c;

    while(Read(STDIN_FILENO, &c, 1) != 0)
    {
        Write(STDOUT_FILENO, &c, 1);
    }
    exit(0);
}
```

**读取时遇到 EOF。** 假设我们准备从一个文件中读取，该文件从当前文件位置起只有 20 个字节，而我们以 50 字节大小的块来读这个文件。那么下一个 `read` 将返回一个不足值 20，再下一个 `read` 将通过返回不足值 0 来发出 EOF 信号。

**从终端读取文本行。** 如果打开的文件与终端（即键盘和显示器）相关联，那么每个 `read` 函数将一次传送一个文本行，返回一个等于文本行大小的不足值。

**读写网络套接字。** 如果打开的文件对应一个网络套接字（第 11.4 节），那么内部缓冲约束和长时间的网络延迟可能导致 `read` 和 `write` 返回不足值。当你调用 Linux 管道（一种进程间通信机制，不在本书讨论范围内）上的 `read` 和 `write` 时，也会出现不足值。

在实践中，从磁盘文件读取时，除了在 EOF 处，永远不会遇到不足值，向磁盘文件写入时也从不会遇到不足值。然而，如果你想构建健壮（可靠）的网络应用程序，

## 10.5 用 Rio 包健壮地读写

在本节中，我们将开发一个称为 Rio（健壮 I/O，Robust I/O）的 I/O 包，它会自动为你处理这些不足值。Rio 包在网络程序等可能遭遇不足值的应用中，提供了方便、健壮且高效的 I/O。Rio 提供了两种不同类型的函数：

**无缓冲的输入输出函数。** 这些函数直接在内存和文件之间传送数据，没有应用级缓冲。它们对于将二进制数据读写到网络和从网络读写二进制数据特别有用。

**带缓冲的输入函数。** 这些函数允许你高效地从文件中读取文本行和二进制数据，文件的内容缓存在应用级缓冲区中，类似于为标准 I/O 函数（如 `printf`）提供的缓冲区。与文献 [110] 中介绍的带缓冲 I/O 例程不同，带缓冲的 Rio 输入函数是线程安全的（第 12.7.1 节），可以在同一描述符上任意交替使用。例如，你可以从一个描述符读一些文本行，然后读一些二进制数据，再读一些文本行。

介绍 Rio 例程的原因有两个：首先，我们将在接下来两章中开发的网络应用程序中使用它们；其次，通过研究这些例程的代码，你将对 Unix I/O 有更深入的了解。

### 10.5.1 Rio 无缓冲的输入输出函数

应用程序可以通过调用 `rio_readn` 和 `rio_writen` 函数在内存和文件之间直接传送数据。

```c
#include "csapp.h"

ssize_t rio_readn(int fd, void *usrbuf, size_t n);
ssize_t rio_writen(int fd, void *usrbuf, size_t n);

返回：若成功则为传送的字节数，若为 EOF 则为 0（仅 rio_readn），若出错则为 -1
```

`rio_readn` 函数从描述符 `fd` 的当前文件位置最多传送 n 个字节到内存位置 `usrbuf`。类似地，`rio_writen` 函数从位置 `usrbuf` 传送 n 个字节到描述符 `fd`。`rio_readn` 函数只有在遇到 EOF 时才会返回不足值，`rio_writen` 函数从不返回不足值。对 `rio_readn` 和 `rio_writen` 的调用可以在同一描述符上任意交替使用。

### 10.5.2 Rio 带缓冲的输入函数

假设我们想编写一个统计文本文件行数的程序，该怎么做？一种方法是使用 `read` 函数每次将 1 个字节从文件传送到用户内存，检查每个字节是否为换行符。这种方法的缺点是效率低下，需要对文件中的每个字节执行一次内核陷阱。

一种更好的方法是调用一个包装函数（`rio_readlineb`），它从内部读缓冲区复制一个文本行，在缓冲区变空时自动调用 `read` 来重新填充缓冲区。对于既包含文本行又包含二进制数据的文件（例如第 11.5.3 节中描述的 HTTP 响应），我们还提供了 `rio_readn` 的带缓冲版本 `rio_readnb`，它从与 `rio_readlineb` 相同的读缓冲区传送原始字节。

```c
#include "csapp.h"

void rio_readinitb(rio_t *rp, int fd);
    返回：无

ssize_t rio_readlineb(rio_t *rp, void *usrbuf, size_t maxlen);
ssize_t rio_readnb(rio_t *rp, void *usrbuf, size_t n);
    返回：若成功则为读取的字节数，若为 EOF 则为 0，若出错则为 -1
```

每个打开的描述符调用一次 `rio_readinitb` 函数，它将描述符 `fd` 与地址 `rp` 处的 `rio_t` 类型读缓冲区关联起来。

`rio_readlineb` 函数从文件 `rp` 读取下一个文本行（包括结尾的换行符），将其复制到内存位置 `usrbuf`，并用 NULL（零）字符结束该文本行。`rio_readlineb` 函数最多读取 `maxlen-1` 个字节，为终止 NULL 字符留出空间。超过 `maxlen-1` 个字节的文本行会被截断并以 NULL 字符结尾。

`rio_readnb` 函数从文件 `rp` 最多读取 n 个字节到内存位置 `usrbuf`。对 `rio_readlineb` 和 `rio_readnb` 的调用可以在同一描述符上任意交替使用。但是，对这些带缓冲函数的调用不应与对无缓冲 `rio_readn` 函数的调用交替使用。

在本书的其余部分，你将看到许多 Rio 函数的例子。图 10.5 展示了如何使用 Rio 函数将文本文件逐行从标准输入复制到标准输出。

图 10.6 展示了读缓冲区的格式以及初始化它的 `rio_readinitb` 函数的代码。`rio_readinitb` 函数建立一个空的读缓冲区，并将一个打开的文件描述符与该缓冲区关联起来。

```c
ssize_t rio_readn(int fd, void *usrbuf, size_t n)
{
    size_t nleft = n;
    ssize_t nread;
    char *bufp = usrbuf;

    while (nleft > 0) {
        if ((nread = read(fd, bufp, nleft)) < 0) {
            if (errno == EINTR) /* 被信号处理程序返回中断 */
                nread = 0;     /* 再次调用 read() */
            else
                return -1;     /* errno 由 read() 设置 */
        }
        else if (nread == 0)
            break; /* EOF */
        nleft -= nread;
        bufp += nread;
    }
    return (n - nleft); /* 返回 >= 0 */
}
```

```c
static ssize_t rio_read(rio_t *rp, char *usrbuf, size_t n)
{
    int cnt;

    while (rp->rio_cnt <= 0) { /* 如果缓冲区为空则重新填充 */
        rp->rio_cnt = read(rp->rio_fd, rp->rio_buf,
                                    sizeof(rp->rio_buf));
        if (rp->rio_cnt < 0) {
            if (errno != EINTR) /* 被信号处理程序返回中断 */
                return -1;
        }
        else if (rp->rio_cnt == 0) /* EOF */
            return 0;
        else
            rp->rio_bufptr = rp->rio_buf; /* 重置缓冲区指针 */
    }

    /* 从内部缓冲区复制 min(n, rp->rio_cnt) 个字节到用户缓冲区 */
    cnt = n;
    if (rp->rio_cnt < n)
        cnt = rp->rio_cnt;
    memcpy(usrbuf, rp->rio_bufptr, cnt);
    rp->rio_bufptr += cnt;
    rp->rio_cnt -= cnt;
    return cnt;
}
```

## 10.7 读取目录内容

应用程序可以使用 `readdir` 系列函数来读取目录的内容。

```c
#include <sys/types.h>
#include <dirent.h>

DIR *opendir(const char *name);
返回：若成功则为指向目录流的指针，若出错则为 NULL
```

`opendir` 函数接受一个路径名，并返回指向目录流的指针。流是一个有序列表项的抽象，在本例中是一组目录项的列表。

```c
#include <dirent.h>

struct dirent *readdir(DIR *dirp);
    返回：若成功则为指向下一个目录项的指针，若没有更多条目或出错则为 NULL
```

每次调用 `readdir` 都返回指向流 `dirp` 中下一个目录项的指针，如果没有更多条目则返回 NULL。每个目录项的结构形式如下：

```c
struct dirent {
    ino_t d_ino;       /* inode 号 */
    char  d_name[256]; /* 文件名 */
};
```

虽然某些版本的 Linux 包含其他结构成员，但这两个成员是所有系统共有的标准成员。`d_name` 成员是文件名，`d_ino` 是文件位置。

```c
#include <dirent.h>
int closedir(DIR *dirp);
返回：若成功则为 0，若出错则为 -1
```

`closedir` 函数关闭流并释放其所有资源。图 10.11 展示了如何使用 `readdir` 读取目录内容。

## 10.8 共享文件

Linux 文件可以通过多种不同方式共享。除非对内核如何表示打开的文件有清晰的认识，否则文件共享的概念可能令人困惑。内核用三个相关的数据结构来表示打开的文件：

**描述符表**（descriptor table）。每个进程都有其独立的描述符表，表项由进程打开的文件描述符来索引。每个打开的描述符表项指向文件表中的一个表项。

**文件表**（file table）。打开文件的集合由一个文件表来表示，所有进程共享这张表。每个文件表项由（就我们的目的而言）当前文件位置、引用计数（即当前指向该表项的描述符表项数），以及一个指向 v-node 表中对应表项的指针组成。关闭一个描述符会减少相应文件表项中的引用计数。内核只有在文件表项的引用计数为零时才会删除该表项。

**v-node 表**（v-node table）。与文件表一样，v-node 表由所有进程共享。每个表项包含 `stat` 结构中的大部分信息，包括 `st_mode` 和 `st_size` 成员。

## 10.9 I/O 重定向

Linux shell 提供了 I/O 重定向操作符，允许用户将标准输入和输出与磁盘文件关联起来。例如，键入

```
linux> ls > foo.txt
```

会使 shell 加载并执行 `ls` 程序，标准输出被重定向到磁盘文件 `foo.txt`。正如我们将在第 11.5 节看到的，Web 服务器在代表客户端运行 CGI 程序时也会执行类似的重定向。那么 I/O 重定向是如何工作的？一种方法是使用 `dup2` 函数。

```c
#include <unistd.h>
int dup2(int oldfd, int newfd);
返回：若成功则为非负描述符，若出错则为 -1
```

`dup2` 函数将描述符表项 `oldfd` 复制到描述符表项 `newfd`，覆盖描述符表项 `newfd` 以前的内容。如果 `newfd` 已经打开，则 `dup2` 在复制 `oldfd` 之前先关闭 `newfd`。

假设在调用 $\text{dup2}(4,1)$ 之前，我们有如图 10.12 所示的情况，其中描述符 1（标准输出）对应于文件 A（比如一个终端），描述符 4 对应于文件 B（比如一个磁盘文件）。A 和 B 的引用计数都等于 1。图 10.15 展示了调用 $\text{dup2}(4,1)$ 之后的情况。两个描述符现在都指向文件 B；文件 A 已关闭并且其文件表和 v-node 表项已删除；文件 B 的引用计数已递增。从这一刻起，任何写到标准输出的数据都被重定向到文件 B。

## 10.10 标准 I/O

C 语言定义了一组更高级的输入输出函数，称为标准 I/O 库，为程序员提供了 Unix I/O 的更高级替代方案。该库（`libc`）提供了打开和关闭文件（`fopen` 和 `fclose`）、读写字节（`fread` 和 `fwrite`）、读写字符串（`fgets` 和 `fputs`）以及格式化 I/O（`scanf` 和 `printf`）等函数。

标准 I/O 库将一个打开的文件模型化为一个流（stream）。对程序员来说，流是一个指向 `FILE` 类型结构的指针。每个 ANSI C 程序开始时都有三个打开的流：`stdin`、`stdout` 和 `stderr`，分别对应于标准输入、标准输出和标准错误：

```c
#include <stdio.h>
extern FILE *stdin;   /* 标准输入（描述符 0） */
extern FILE *stdout;  /* 标准输出（描述符 1） */
extern FILE *stderr;  /* 标准错误（描述符 2） */
```

`FILE` 类型的流是对文件描述符和流缓冲区的抽象。流缓冲区的目的与 Rio 读缓冲区相同：最小化代价高昂的 Linux I/O 系统调用次数。例如，假设我们有一个程序反复调用标准 I/O `getc` 函数，每次调用从文件返回下一个字符。当第一次调用 `getc` 时，库通过单次调用 `read` 函数填充流缓冲区，然后将缓冲区中的第一个字节返回给应用程序。只要缓冲区中有未读字节，后续的 `getc` 调用就可以直接从流缓冲区提供服务。

Unix I/O 模型在操作系统内核中实现，通过 `open`、`close`、`lseek`、`read`、`write` 和 `stat` 等函数向应用程序提供服务。更高级的 Rio 和标准 I/O 函数是"构建在"（使用）Unix I/O 函数之上实现的。Rio 函数是专门为本教材开发的、针对 `read` 和 `write` 的健壮包装器，能自动处理不足值，并提供一种高效的带缓冲方法来读取文本行。标准 I/O 函数提供了比 Unix I/O 函数更完整的带缓冲替代方案，包括 `printf` 和 `scanf` 等格式化 I/O 例程。

那么，程序中应该使用哪些函数呢？以下是一些基本准则：

**G1：尽可能使用标准 I/O 函数。** 标准 I/O 函数是对磁盘和终端设备进行 I/O 的首选方法。大多数 C 程序员在整个职业生涯中都只使用标准 I/O，从不使用底层的 Unix I/O 函数（可能除了 `stat`，它在标准 I/O 库中没有对应函数）。在可能的情况下，我们建议你也这样做。

**G2：不要使用 scanf 或 rio_readline 读取二进制文件。** 像 `scanf` 和 `rio_readline` 这样的函数是专门为读取文本文件而设计的。学生常犯的一个错误是使用这些函数读取二进制数据，导致程序以奇怪而不可预测的方式失败。例如，二进制文件中可能布满了大量的 `0xa` 字节，与文本行的终止毫无关系。

**G3：对网络套接字的 I/O 使用 Rio 函数。** 遗憾的是，当我们尝试在网络上进行输入输出时，标准 I/O 会产生一些棘手的问题。正如我们将在第 11.4 节看到的，网络的 Linux 抽象是一种称为套接字的文件。与任何 Linux 文件一样，套接字通过文件描述符引用，在本例中称为套接字描述符。应用程序进程通过读写套接字描述符与运行在其他计算机上的进程通信。

标准 I/O 流在某种意义上是全双工的——程序可以在同一流上执行输入和输出。然而，流有一些文档不完善的限制，与套接字上的限制相互冲突：

**限制 1：跟随输出函数的输入函数。** 如果没有在中间插入对 `fflush`、`fseek`、`fsetpos` 或 `rewind` 的调用，输入函数不能跟随输出函数。`fflush` 函数清空与流相关联的缓冲区，后三个函数使用 Unix I/O `lseek` 函数来重置当前文件位置。

**限制 2：跟随输入函数的输出函数。** 如果没有在中间插入对 `fseek`、`fsetpos` 或 `rewind` 的调用，输出函数不能跟随输入函数，除非输入函数遇到了文件结尾。

---

<!-- Page 0936 -->

这些限制给网络应用程序带来了问题，因为在套接字上使用 `lseek` 函数是非法的。对流 I/O 的第一个限制可以通过在每次输入操作之前刷新缓冲区的规则来解决。然而，解决第二个限制的唯一方法是在同一打开套接字描述符上打开两个流，一个用于读，一个用于写：

```c
FILE *fpin, *fpout;
fpin  = fdopen(sockfd, "r");
fpout = fdopen(sockfd, "w");
```

但这种方法也有问题，因为它要求应用程序对两个流都调用 `fclose`，以释放与每个流相关联的内存资源并避免内存泄漏：

```c
fclose(fpin);
fclose(fpout);
```

每个操作都试图关闭同一个底层套接字描述符，因此第二个关闭操作将会失败。对于顺序程序这不是问题，但在线程化程序中关闭一个已经关闭的描述符是灾难的根源（见第 12.7.4 节）。

因此，我们建议不要在网络套接字上使用标准 I/O 函数进行输入输出，而应使用健壮的 Rio 函数。如果需要格式化输出，可以使用 `sprintf` 函数在内存中格式化字符串，然后用 `rio_writen` 将其发送到套接字。如果需要格式化输入，可以使用 `rio_readline` 读取整个文本行，然后使用 `sscanf` 从文本行中提取不同的字段。

## 10.12 小结

Linux 提供了少量基于 Unix I/O 模型的系统级函数，允许应用程序打开、关闭、读写文件，获取文件元数据，以及执行 I/O 重定向。Linux 的 `read` 和 `write` 操作受不足值限制，应用程序必须预见并正确处理。应用程序应使用 Rio 包而不是直接调用 Unix I/O 函数，Rio 包通过反复执行读写操作直到所有请求的数据传送完毕，自动处理不足值。

Linux 内核使用三个相关的数据结构来表示打开的文件。描述符表中的表项指向打开文件表中的表项，后者又指向 v-node 表中的表项。每个进程都有自己独立的描述符表，而所有进程共享相同的打开文件表和 v-node 表。理解这些结构的一般组织，有助于理解文件共享和 I/O 重定向。

标准 I/O 库是在 Unix I/O 之上实现的，提供了一套强大的更高级 I/O 例程。对大多数应用而言，标准 I/O 是

---

<!-- Page 0937 -->

Unix I/O 更简单、更受青睐的替代方案。然而，由于标准 I/O 和网络文件之间存在一些相互不兼容的限制，对于网络应用程序应该使用 Unix I/O 而非标准 I/O。

## 练习题解答

### 练习题 10.1 解答（第 931 页）

Unix 进程开始时，描述符 0（stdin）、1（stdout）和 2（stderr）已分配给打开的描述符。`open` 函数总是返回当前未打开的最小描述符，因此第一次调用 `open` 返回描述符 3。调用 `close` 函数释放描述符 3。最后调用 `open` 返回描述符 3，因此程序输出为 `fd2 = 3`。

### 练习题 10.2 解答（第 944 页）

描述符 $fd1$ 和 $fd2$ 各自有自己的打开文件表项，因此每个描述符对于 `foobar.txt` 都有自己的文件位置。从 $fd2$ 读取时读取的是 `foobar.txt` 的第一个字节，输出为：

```
c = f
```

而不是你可能最初认为的：

```
c = o
```

### 练习题 10.3 解答（第 944 页）

回想一下，子进程继承父进程的描述符表，且所有进程共享同一个打开文件表。因此，父进程和子进程中的描述符 `fd` 都指向同一个打开文件表项。当子进程读取文件的第一个字节时，文件位置增加 1。因此，父进程读取第二个字节，输出为：

```
c = o
```

### 练习题 10.4 解答（第 945 页）

要将标准输入（描述符 0）重定向到描述符 5，需要调用 `dup2(5, 0)`，或等价地调用 `dup2(5, STDIN_FILENO)`。

### 练习题 10.5 解答（第 946 页）

乍一看，你可能认为输出为：

```
c = o
```

但因为我们将 `fd1` 重定向到 `fd2`，`Dup2(fd2, fd1)` 使 `fd1` 指向与 `fd2` 相同的打开文件表项。在执行 `Dup2` 之前，`Read(fd2, &c, 1)` 已经将 `fd2` 的文件位置推进到 1（读取了第一个字符 `'f'`）。因此，之后从 `fd1` 读取时使用的是 `fd2` 的文件位置 1，读到的是 `'o'`，实际输出为：

```
c = o
```
